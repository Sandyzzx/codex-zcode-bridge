# ADR-015：Master Skill 显式调用授权与渐进式加载

> Status: DECISION
> Decision: Accepted（用户于 2026-10-24 要求审查并合入 Master Skill P0 + 渐进式加载候选包）
> Date: 2026-10-24

## Context

现有 Master Skill 将触发、策略、派发、监控、恢复和汇报全部放在入口中，容易把历史调用误当作新目标的 Bridge 授权，也使只读状态查询加载无关流程。外部候选基于 2026-10-21 快照；必须与当前未提交内容三方核对，不能覆盖本地后续规则。

## Decision

1. **先确认执行器授权。** 新独立目标默认不使用 Bridge；用户明确选择当前目标使用 ZCode/Bridge，或有覆盖当前目标的显式会话/持续目标授权，才可提交新任务。历史调用、Skill 加载、普通开发授权和 Goal 的存在本身都不扩大该授权。同一已授权任务内必要监控、验收及证据驱动返工可继续；下一阶段必须处于原目标授权范围且决策门满足，或另获授权。
2. **默认由 Master 自动选策略。** `auto` 只描述 Master 在有效授权内选择 `whole_task` 或 `staged` 的偏好。ADR-010 的完整交付优先、Worker 自主调查/实现/测试/修复闭环、被动监控、预算和独立验收仍有效；存在真实决策门时只交付当前可独立验收阶段。用户指定策略仍不能越过授权或审批门。
3. **入口保留不可遗漏的约束。** 根 Skill 保留授权、Worker 自主权、执行目录互斥、关键决定升级、权限审批、额度耗尽/取消停止及独立验收。细节拆入按行为路由的 references；首次派发前读监控指引，持续目标首次派发前读 Goal 指引，终态/异常时读恢复指引。只读查询不预载整个目录。
4. **运行合同不变。** 不新增 TaskPackage 字段、MCP 工具或 schema，不修改 Prompt Builder、运行时状态、持久化策略或依赖。`auto` 不能随工具参数发送。Skill 授权是模型行为约束，不是服务端强制鉴权或可信宿主凭证；权限边界仍按既有合同和具体用户许可处理。
5. **验证分层。** 记录来源哈希、三方差异、安全规则迁移、链接/结构检查与离线场景的实际证据。静态检查、离线模型输出、真实 Worker 回归和真实任务 A/B 分别报告；入口字符减少不推导 token、费用或成功率改善。合入仓库不等于更新已安装插件、提交或发布。

## Rationale

将“是否获准使用 Bridge”和“如何组织已授权交付”分开，可避免历史授权外溢；保留完整交付优先，继续复用 ADR-010 和既有 Worker 能力。按操作加载参考文档能缩短入口，但安全前置和跨步骤衔接必须显式保留。

## Consequences

- 根 Skill 与八份 references 共同构成 Master 指引；本地新增的空数组、可省略参数、锁、报告修复及观测来源规则继续保留。
- 自动策略不成为新的服务端状态；只读查询不构成新任务授权，Goal 也不是执行器授权凭证。
- 实际模型遵循率和 token 收益需要独立实测；离线评估不证明真实 provider、权限往返或长期任务可靠性。
