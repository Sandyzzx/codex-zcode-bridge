# SQLite v13 Retirement

> Status: RESEARCH
> Date: 2026-11-21
> Baseline: `origin/preview` `c1245a02f8f9d4b6e1102eabac230b657d85de9b` (tree `b687bca64ce766b945178cf8af44442cf57f90b3`)
> Implementation: `55bc5af88f3ed57f3c1a258eac0a0cc89e29a4f0` (tree `5247693b045c0d6a70c7391757d96f97c7501069`)

## Outcome

当前生产支持统一为 `SQLite v14 ONLY`。v13 自动升级、离线复制升级、升级恢复/回滚、冻结 DDL、升级 CLI、构建/打包引用及升级成功路径测试均已删除。v14 Schema 未修改，历史 v14 数据结构和生命周期合同保持不变。

发现 v13 数据库时，Store 和 Lifecycle Gate 返回稳定的 `unsupported_sqlite_schema`，提示只支持 v14。v13 数据库存在 `-wal`/`-shm` 时，预检只读主库头和 WAL 中最后一个已提交的 page 1，不创建 SQLite 句柄，因此不改变任一现场文件。发现 `*.v13-v14-pending.json` 时保留原字节并拒绝，不做恢复、重命名、删除或 Fresh Bootstrap。

## Implemented Cleanup

- 删除 `upgradeV13Copy()`、`autoUpgradeV13()`、v13 DDL 分支和 `schema-v13.sql`。
- 删除 `src/cli/upgrade-sqlite-v14.ts`、生成 bundle、BOM/验证器/Clean Entrypoints 构建引用。
- 删除自动升级 Marker 的创建、恢复、回滚和 Host 启动参数接线。
- 保留 `migration_runs`、`authority_switch`、`json_artifacts`、`migrated_task_results`、`migrated_task_events`、`manager_admin_abandonments`、`runtime_task_events` 及旧 v14 Administrative Schema 兼容。
- `interrupted_by_upgrade` 仅保留为历史 v14 Result/Event 事实，不再由升级产生。
- 旧 `authority: "json"` 配置仍仅作为安装兼容提示选择 Fresh SQLite v14，不恢复 JSON Authority。
- ADR-043 将 ADR-026/029/036/038 中的 v13 升级段落标记为 SUPERSEDED / RETIRED；历史 ADR 正文保留。
